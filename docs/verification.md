# 验证记录

整理日期：2026-11-01。此页根据开发期间保存的实际 HTTP、媒体文件与浏览器操作记录整理。公开记录省略本机绝对路径、私人配置和运行目录。

## 发布副本验证

在同一台 macOS 机器的独立源码目录中执行，未复制原有 `node_modules`、构建目录或个人数据：

- `bun install --frozen-lockfile`：通过，Bun 1.3.14。
- 网页与服务端各自的 `typecheck`：通过。
- `bun run build:server`：通过，仍有前端大体积 chunk 的构建提示。
- 使用空数据目录启动服务：主页 HTTP 200；带同源请求头的项目列表接口 HTTP 200，项目数为 0。
- 不带同源信息的项目列表请求返回 HTTP 403，符合本地工作区接口限制。
- 暂存前扫描未发现密钥格式；在进程内与现有配置的实际凭据逐项比对，未发现匹配。

首次类型检查曾因网页/服务读取桌面配置而依赖尚未下载的 `.hutch/devkit` 类型目录。发布版已将共享应用元信息放到 `appMetadata.ts`，保留桌面配置本身的 SDK 类型校验。以上构建与类型检查结果来自修正后的副本，不代表其他操作系统已验收。

## 制作门禁与候选采用

以下 16 项记录均通过，操作使用验收副本，未在这一轮新增付费生成请求。

| 镜头缺少角色参考图 | HTTP 422，提示补齐 |

| 导入已有视频 | HTTP 200 |
| 创建视频候选 | 保留已采用视频 |
| 视频候选仅继承关键帧 | 不能作为已生成视频采用 |
| 仅修改字幕 | 原视频素材路径保持不变 |

| 撤销采用 | 恢复先前的已采用版本 |

## 共享界面

- 桌面正式包中的网页资源与当前前端构建一致。
- 桌面模式页面能打开共享首页、创建空画布、增加文字/视频节点并打开导演助手。
- 独立网页验收项目中，撤销后节点由 2 个变为 1 个，重做恢复 2 个；保存后刷新，两个节点仍在。
- 既有真实片段的预览、字幕、时间轴和导演助手可显示。
- 原有两个桌面项目文件在本轮更新前后哈希一致。

原生 WKWebView 的全部交互与保存弹窗尚未完成自动化验收。测试期间曾观察到桌面服务结束，原因未确认；重启后恢复。连接失败时画布暂停后续写入，界面提示重新打开项目，未将此次中断计为保存成功。
