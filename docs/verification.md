## 2026-11-02 首页至成片的连贯制作验收

使用独立验收数据目录，通过真实浏览器操作和已配置模型完成，未在原用户项目上生成或修改素材。

| 场景 | 实际结果 |
| --- | --- |
| 首页输入“生成一张猫图” | 进入图片确认窗，调用 GPT Image 2；未创建漫剧工作流或六镜剧本 |
| 图片预览与下载 | 放大成功；浏览器保存 PNG 成功 |
| 将橘猫改成白猫 | 使用原图和当前修改要求生成新图，原图保留；观察到毛色改变、姿势与窗边构图保留，仅为单样本结果 |
| 使用白猫图片做视频 | Seedance 1.0 Pro Fast，5 秒任务成功，视频保存在当前节点 |
| 加入成片并聊天改字幕 | 字幕“午后的窗边”在0.5—4秒显示，复用原视频素材路径，无新增图片／视频任务 |
| 导入配乐并导出 | 使用已有示例环境音乐，音量25%；MP4为5.000秒、1920×1080、30fps、H.264与AAC |
| 成片有效性 | FFmpeg全片解码退出码0；浏览器播放推进并到达结尾；下载成功；检查1秒画面包含预期字幕 |
| 模板填写 | 自定义名称和侦探画面描述写入实际节点及模板记录；创建时媒体任务为0 |
| 素材引用 | “交给助手”添加原生@引用，菜单列出当前创作画布的文字和真实图片输出，未发送新生成请求 |
| 首页讨论 | 原要求带入工作台，真实文字模型回复“收到”，无媒体任务 |
| 重复与错误输入 | 同一生成请求重放，任务数保持4；模板创建重放返回原目录；相同创建ID变更内容HTTP409；伪造图片HTTP400 |

本轮有2个真实图片任务、1个真实视频任务和1个本地导出任务。字幕编辑中出现一次工具参数校验失败，助手修正后成功，不应表述为全流程无异常。供应商真实费用与完整API调用次数暂无统计，不能据此计算成本收益。

测试中发现并修复了结果编辑递归继承旧“橘猫”要求的问题。结果派生节点只使用直接参考图与本次指令，原始来源连线仍保留。人工确认模式、实际可用模型和媒体开关的文案也已统一。

此验收不代表双角色六镜三十秒漫剧、跨镜一致性、自动配音、远端任务取消和异常恢复已完成验收。

## 发布副本验证

在同一台 macOS 机器的独立源码目录中执行，未复制原有 `node_modules`、构建目录或个人数据：

- `bun install --frozen-lockfile`：通过，Bun 1.3.14。
- 网页与服务端各自的 `typecheck`：通过。
- `bun run build:server`：通过，仍有前端大体积 chunk 的构建提示。
- 使用空数据目录启动服务：主页 HTTP 200；带同源请求头的项目列表接口 HTTP 200，项目数为 0。
- 不带同源信息的项目列表请求返回 HTTP 403，符合本地工作区接口限制。
- 暂存前扫描未发现密钥格式；在进程内与现有配置的实际凭据逐项比对，未发现匹配。

首次类型检查曾因网页/服务读取桌面配置而依赖尚未下载的 `.hutch/devkit` 类型目录。发布版已将共享应用元信息放到 `appMetadata.ts`，保留桌面配置本身的 SDK 类型校验。以上构建与类型检查结果来自修正后的副本，不代表其他操作系统已验收。

## 模板库验证（2026-11-02）

使用独立数据目录进行实际 HTTP 和浏览器操作，未向用户配置的模型提交生成任务：

- 10 个模板创建均返回 HTTP 200；6 个视频模板各有文字、图片、视频 3 个节点和 2 条连线，4 个图片模板各有 2 个节点和 1 条连线。新建项目的任务列表均为空。
- 同一请求 ID 重试返回原项目；更换请求 ID 创建独立项目。原画布内容未被覆盖。
- 同一请求 ID 改变内容返回 HTTP 409；未知模板或将模板用于剪辑项目返回 HTTP 400；缺少本地同源请求信息返回 HTTP 403；原空白项目创建仍返回 HTTP 200。
- 浏览器完成全库分类筛选、详情查看、ESC 关闭、图片模板与视频模板创建。编辑文字并保存后刷新，内容与节点数量保留。
- 浏览器断网时显示创建错误、恢复网络后可重试进入项目。最终界面将通用英文网络错误改为中文连接与重试提示。
- 1440 像素宽度下显示 5 列共两排，390 像素宽度下显示 2 列，无页面横向溢出。10 张封面均能加载。
- 更新后的正式网页版创建咖啡模板成功，带入 3 个节点、9:16 画幅和 5 秒时长；视频生成在首帧缺失时提示先完成上游节点。
- 现有桌面正式包已更新并重新启动，服务返回的新入口与共享前端构建一致。桌面接口创建六格分镜模板返回 HTTP 200，产生 2 个节点、1 条连线与 9:16 画幅；本次未自动操作原生窗口。
- 更新前后的原项目文件、API 配置文件、图标和 Info.plist 哈希均保持一致。
- Web、Server 和桌面类型检查通过；Web、Server 及桌面主进程构建通过。前端仍有大体积 chunk 构建提示。

封面使用内置 imagegen 独立生成，未使用用户的 API Key，也未复制第三方模板封面。以上结果验证模板选择、初始化和编辑流程，不代表已完成 10 个模板的真实成片验收。


## 单框首页与简报确认验证（2026-11-02）

本轮在独立数据目录使用真实 DeepSeek 文字接口完成简报整理和剧本起草，没有提交图片或视频生成任务。

- 输入来自首页“产品广告”入口：20 秒竖屏咖啡短片，无人出镜，保持同一只白瓷杯，不添加品牌或功效承诺；上传 coffeeMoment.png 作为画面参考。
- `/director/brief` 返回工作标题、故事摘要和明确要求，“无人出镜”提取正确。相同请求 ID 的紧接重试返回 HTTP 200，耗时约 206 ms；此结果来自进程内缓存，不代表模型生成耗时。
- 浏览器清空角色字段后提交显示缺项错误；返回首页再打开简报，人工修改的标题保留。断网提交显示中文错误，联网重试后成功创建项目。
- `/director/start` 生成并保存剧本 V1：2 个场景、0 个角色，目标时长 20 秒、目标镜头数 4。此时尚未生成分镜或视频。参考图复制到项目 assets，文件哈希与上传原图一致，临时输入已清理。
- 确认无人出镜剧本后进入分镜阶段，“从已确认内容生成分镜”可用，不会被空角色列表阻断。本轮没有点击生成分镜。
- 浏览器完成空输入校验、Markdown 导入、参考图上传、角色模板详情与模板全库入口操作。390 像素视口没有横向溢出；桌面和小屏分别保留截图。
- 实际 HTTP 校验覆盖缺少同源信息（403）、无效画幅（400）、供应商与模型缺一（400）、未知模型（422）和无效图片内容（400）。无效图片在调用模型前被拒绝。
- 代码审查修复了大图 base64 正则误拒、AI 建议覆盖人工设定、剧本文字异步导入的状态竞态。建议追加与超长提示通过类型检查，未单独做真实模型建议样本验收。
- Web、Server、桌面类型检查与构建通过。正式网页版和现有桌面包已更新；两端返回相同前端入口，新简报路由均能拒绝未知模型。桌面原生窗口未自动操作。
- 更新前后 25 个已有项目、配置、图标与 Info.plist 文件校验一致。967 个公开候选源文件中未发现本地配置内的 3 个实际密钥值；未推送本轮改动。

尚未验证真实供应商超时、断连后计费、跨进程恢复或完整媒体生成。上述结果验证首页入口、文字简报确认与项目保存，不代表完整漫剧制作质量或业务收益。
